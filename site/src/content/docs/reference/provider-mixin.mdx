`ProviderMixin` creates a class that owns the player store and the media attach lifecycle. It publishes the store and registration APIs through context, then calls `store.attach()` when a media element is available. A container is optional.

### Store lifecycle

The store is created when the element is constructed. On `connectedCallback`, the mixin publishes three context values to its descendants:

| Context | Published value |
| --- | --- |
| `playerContext` | The store, consumed by <DocsLink slug="reference/player-controller">`PlayerController`</DocsLink> and other controllers |
| `mediaContext` | The current media, which may be `null`, and a `registerMedia()` callback that returns a release function |
| `containerContext` | The current container, which may be `null`, and a `registerContainer()` callback that returns a release function |

The attachment flow is:

1. A custom media element registers through `mediaContext`, or the provider discovers the first descendant `<video>` or `<audio>` element.
2. A container can register through `containerContext`.
3. Once media is available, the provider calls `store.attach({ media, container })`. `media` is required, while `container` can be `null`.
4. When the selected media or container changes, the provider detaches the previous target and attaches the new one.

Each release function removes only the element that registered it, so disconnecting an older element cannot clear a newer registration. The provider watches for plain `<video>` and `<audio>` elements as they are added, removed, or replaced.

On `disconnectedCallback`, the mixin detaches the current media target but keeps the store alive. An element moved in the DOM reconnects without losing state. The store is destroyed in `destroyCallback`.

### When to split provider and container

Use `ProviderMixin` with the independently extensible <DocsLink slug="reference/player-container">`ContainerElement`</DocsLink> when the store owner is a different element from the container:

```ts
import { ContainerElement, createPlayer, UIElement } from '@videojs/html';

const { ProviderMixin } = createPlayer({ features: videoFeatures });

// Layout shell owns the store
class AppShell extends ProviderMixin(UIElement) {}

// Content region is the fullscreen target and container reference
class VideoRegion extends ContainerElement {}
```
